## Quyết định của operator

Operator muốn có một method controller rất đơn giản, ví dụ `GetHelloWorld`, được bảo vệ trực tiếp bởi:

```text
Authentication scheme: WpfJwt
Authorization policy: WpfInstallBootstrap
```

Khi WPF dùng chính `WpfJwt` vừa nhận để gọi method này và UI hiển thị đúng chuỗi do controller trả về, đó là physical proof dễ nhìn rằng:

```text
WPF đã nhận token
-> gửi Bearer token
-> ApiServer xác thực WpfJwt
-> policy WpfInstallBootstrap PASS
-> request thực sự vào method controller
-> controller trả marker
-> WPF nhận và hiển thị marker từ response
```

Endpoint này là proof bổ sung. Nó không thay thế `/api/platform-v0/wpf/bootstrap/me`, vì `/bootstrap/me` vẫn chịu trách nhiệm xác minh exact Tenant/POS/attempt/local-installation identity.

## Mục tiêu

1. Thêm một protected controller endpoint đơn giản tên method `GetHelloWorld`.
2. Endpoint chỉ chạy khi `WpfJwt` authentication và `WpfInstallBootstrap` policy PASS.
3. Endpoint trả một marker cố định rõ ràng và server timestamp.
4. WPF gọi endpoint bằng chính WpfJwt sau redeem.
5. WPF hiển thị nguyên văn marker nhận từ API, không tự tạo chuỗi PASS giả.
6. WPF vẫn gọi `/bootstrap/me` và thực hiện toàn bộ identity comparison hiện có.
7. Restart/resume cũng gọi lại protected hello bằng credential đã DPAPI-unprotect, không redeem lần hai.
8. Build/test đầy đủ.
9. Cuối task, Codex phải khởi động lại **ApiServer và PlatformAppV0** từ output mới nhất và để cả hai chạy cho operator tạo Pairing Code mới và physical retest.
10. Không để WPF chạy nền; operator sẽ chạy WPF bằng Visual Studio Debug.

Không làm Phase 2 và không chạm local POS database.

# 1. ApiServer protected GetHelloWorld endpoint

## Canonical endpoint

Tạo endpoint:

```http
GET /api/platform-v0/wpf/bootstrap/hello
Authorization: Bearer <WpfJwt>
```

Method C# phải có tên:

```text
GetHelloWorld
```

Đặt trong controller thuộc ApiServer `PlatformAppV0` Phase 1, ưu tiên cùng controller đang chứa redeem và `/bootstrap/me` nếu boundary vẫn rõ ràng.

## Authorization mask bắt buộc

Endpoint phải được bảo vệ trực tiếp và rõ ràng bằng existing canonical constants/scheme/policy tương đương:

```csharp
[Authorize(
    AuthenticationSchemes = PlatformAppV0Contract.WpfJwtScheme,
    Policy = PlatformAppV0Contract.WpfInstallBootstrapPolicy)]
```

Nếu tên constant hiện tại khác, dùng đúng existing canonical constant nhưng report phải ghi exact name/value mapping.

Không được:

- `[AllowAnonymous]`;
- dùng Platform administrator cookie/JWT;
- dùng Google token;
- dùng fallback authentication scheme không rõ ràng;
- tự kiểm tra token thủ công bên trong method thay cho ASP.NET authentication/policy.

## Response contract đề nghị

Tạo shared response DTO, ví dụ:

```csharp
public sealed record WpfProtectedHelloResponse(
    bool Success,
    bool Authenticated,
    string ResultCode,
    string Message,
    DateTimeOffset ServerUtc,
    string ContractVersion);
```

Success response phải có exact values:

```text
success = true
authenticated = true
resultCode = WPF_JWT_PROTECTED_CONTROLLER_REACHED
message = HELLO_FROM_PLATFORMAPPV0_WPFJWT_PROTECTED_CONTROLLER
contractVersion = platform-app-v0.phase1
serverUtc = current UTC generated by ApiServer
```

Marker `message` phải được tạo trong ApiServer response. WPF không được chỉ hard-code rồi tự hiển thị marker mà không đọc response.

## Method mẫu về intent

Codex phải điều chỉnh theo codebase thật, nhưng intent phải tương đương:

```csharp
[HttpGet("wpf/bootstrap/hello")]
[Authorize(
    AuthenticationSchemes = PlatformAppV0Contract.WpfJwtScheme,
    Policy = PlatformAppV0Contract.WpfInstallBootstrapPolicy)]
public ActionResult<WpfProtectedHelloResponse> GetHelloWorld()
{
    var authenticated = User.Identity?.IsAuthenticated == true;
    return Ok(new WpfProtectedHelloResponse(
        Success: true,
        Authenticated: authenticated,
        ResultCode: PlatformAppV0Contract.WpfJwtProtectedControllerReached,
        Message: "HELLO_FROM_PLATFORMAPPV0_WPFJWT_PROTECTED_CONTROLLER",
        ServerUtc: DateTimeOffset.UtcNow,
        ContractVersion: PlatformAppV0Contract.Version));
}
```

Do authorization đã chạy trước method, `Authenticated` phải là true. Nếu không true, response không được coi là success.

# 2. WPF call chain

## Initial redeem flow

Sau khi redeem trả WpfJwt hợp lệ, WPF phải thực hiện đúng thứ tự:

```text
POST /wpf/pairing/redeem
-> validate redeem contract
-> GET /wpf/bootstrap/hello with Bearer WpfJwt
-> require HTTP 200
-> require success=true
-> require authenticated=true
-> require resultCode=WPF_JWT_PROTECTED_CONTROLLER_REACHED
-> read message and serverUtc from actual response
-> display protected-controller proof
-> GET /wpf/bootstrap/me with same Bearer WpfJwt
-> exact identity comparison
-> DPAPI protect/readback
-> atomic checkpoint write/readback
```

Không được DPAPI-protect token hoặc ghi `ApiAuthorized` checkpoint nếu protected hello hoặc `/bootstrap/me` fail.

## Restart/resume flow

Sau restart:

```text
read ApiAuthorized checkpoint
-> DPAPI-unprotect WpfJwt
-> GET protected hello with stored WpfJwt
-> GET /bootstrap/me with stored WpfJwt
-> compare checkpoint identity
-> RestartResume verified
-> SecondRedeemAvoided=true
```

Không redeem lại.
